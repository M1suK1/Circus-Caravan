## 一、三大改造方向设计方案

### 1. 标签页边缘：手工撕裂羊皮纸不齐边缘（Torn Vellum Deckle Edge）
- **应用范围**：主舞台卷轴容器（`.app-main` 内主工作区外框 / `.atlas-stage-card` / `.modal-scroll` / 抽屉边缘）。
- **视觉目标**：呈现古老牛皮纸手工裁切后的微锯齿毛边、边缘碳化焦褐暗晕与淡淡的折痕纹理，而不是规整的现代直角/圆角矩形。
- **技术实现（双层隔离法）**：
  1. **外层内容宿主**（`.vellum-sheet`）：`position: relative`，正常 `padding` 与排版，**不直接施加任何 `clip-path` 或 SVG 滤镜**。
  2. **底层背景纸片层**（`.vellum-sheet::before`）：`position: absolute; inset: 0; z-index: 0; pointer-events: none;`，使用两套叠加方案之一：
     - **方案 A（推荐 · 零实时算力消耗）**：使用预生成的 **SVG 9-slice `border-image`** 或高精度手绘 **SVG `mask-image` / `clip-path` 多点折线路径** 裁出自然不规则边缘，再由父级容器的 `filter: drop-shadow(0 6px 18px rgba(42, 31, 24, 0.16))` 投出沿着不规则齿牙贴合的真实纸影。
     - **方案 B（动态纸纤维边）**：在独立的 `::before` 伪元素上施加轻量 SVG `<feTurbulence>` + `<feDisplacementMap>`（仅 2px–3px 微扰动纸边），内容层全部 `position: relative; z-index: 1`，确保文字与 `<canvas>` 地图像素 100% 锐利不失真。

### 2. 标签按钮：丝绸书签质感（Silk Ribbon Bookmarks）
- **应用范围**：
  - 左侧导航栏 4 大主功能标签（`地图` / `马车` / `物资` / `记录`）；
  - 地图顶部三级切换（`世界地图` / `区域地图` / `跟随马车周边`）；
  - 物资页子标签（`行军辎重` / `奇幻兽笼` / `货客运`）与模态框切换标签（`LLM 篝火夜谈` / `VN 舞台预览`、`模型网关` / `预设` / `世界书`）。
- **视觉工艺**：
  - **燕尾剪口几何**：书签末端做经典 V 形燕尾缺口（左侧侧边栏书签从左向右伸出、末端剪出燕尾；水平标签栏书签从卷轴顶部向下垂坠、底部剪出燕尾）。
  - **丝绸经纬与光影**：使用多层渐变模拟真丝斜纹反光（高光柔带 + 边缘压暗的锁边暗线 + `1px` 虚线金丝缝线 `border: 1px dashed rgba(246, 224, 174, 0.45)`）。
  - **色系分工**：
    - `地图` / 主选态：绯红绸缎（`#9e3127` → `#7a2018`）配暖金丝线；
    - `马车`：松林墨绿绸缎（`#386147` → `#274733`）；
    - `物资`：古铜琥珀绸缎（`#b37024` → `#8a5215`）；
    - `记录` / 引擎控制台：靛青深蓝绸缎（`#315772` → `#223e54`）。
  - **抽拉微交互**：未选中态缩入纸页边缘一部分；`hover` 时丝带轻柔探出 `4px` 并泛起丝光移动；`active` 激活态完全抽出 `8px–10px` 压在羊皮纸页之上，配合细腻立体投影（遵守 `prefers-reduced-motion`）。

### 3. 嵌在标签页内的功能块：纸质便利贴（Pinned Paper Notes）
- **应用范围**：
  - `地图` 右侧栏信息卡（大区概览、当前驻扎地、视野内据点、边境关口）；
  - `马车` 车厢卡、酒馆招募卡、演员花名册卡、角色卡双栖指派台；
  - `物资` 6 类行军补给卡、奇幻兽笼卡、货客运契约卡；
  - `记录` 隐居进度卡、势力外交卡、电台传闻条。
- **视觉工艺**：
  - **纸张叠层质感**：区别于底层旧羊皮大卷轴（`#F3E7CE`），便利贴采用略浅或微带不同材质色阶的便签纸（米白手账纸 `#FBF5E6`、泛灰再生纸 `#EFE9DA`、牛皮卡纸 `#F2DFBE`），四周去掉重边框，改为极细 `1px` 纸边线 + 轻盈浮动感。
  - **物理固定件（纯 CSS + 小 SVG，零 emoji）**：
    - 重要的行动卡顶部正中贴一段半透明斜纹**亚麻和纸胶带（Washi Tape）**；
    - 警示/城郭据点卡左上角别一枚**铜钉 / 微缩火漆印点**；
  - **微倾与卷角阴影**：
    - 为便签网格引入确定性轻微交替倾角（`nth-child(3n+1)` `-0.45deg`、`3n+2` `+0.4deg`、`3n` `-0.2deg`）；
    - 底部右侧用 `::after` 弧形阴影制造「纸角微翘、贴在底层羊皮纸上」的物理纵深感；
    - **交互反馈**：鼠标 `hover` 或键盘 `:focus-within` 时，便利贴平滑回正为 `rotate(0deg) translateY(-2px)` 并加深投影，方便精确点击内部按钮。

## 二、可行性分析与潜在问题提出（重点风险排查）

总体**完全可行**（纯 CSS + 轻量 SVG 遮罩即可落地，无需引入额外第三方图形库，零打包体积负担）。但在落地实施时有 **5 个具体工程/视觉问题必须在方案阶段提前解决**：

### 问题 1（严重）：SVG 撕裂滤镜直接挂在主容器会糊掉地图 Canvas 与汉字排版
- **问题说明**：如果把 `<feDisplacementMap>` 直接套在承载内容的外层元素上，浏览器会把该元素连同里面的 `<canvas>` 地图线稿、小号等宽数字（`11px–12px`）和汉字一起像素位移，导致文字边缘锯齿模糊、甚至鼠标划线坐标出现 2px 视觉偏差。
- **解决方案**：**必须把「纸张背景伪元素」与「内容层」彻底拆开**——纸张边缘毛刺/撕裂只作用在 `z-index: 0` 的 `::before` 背景片上，主地图 Canvas 与文字区在 `z-index: 1` 的干净图层内渲染，保证画布 100% 清晰、划线坐标零偏差。

### 问题 2（中度）：`clip-path` 会同时切掉 `box-shadow` 与键盘 `focus-visible` 轮廓
- **问题说明**：丝绸书签的燕尾剪口和不规则羊皮纸边缘如果直接用 `clip-path` 裁在 `<button>` 或交互卡片自身上，CSS 的 `box-shadow` 与无障碍 `outline: 2px solid var(--amber)` 会被一并裁没，键盘 Tab 切换时看不见焦点且书签失去了投影层次。
- **解决方案**：`<button>` 宿主元素本身不写 `clip-path`，只承担点击热区、`focus-visible` 焦点环与 `filter: drop-shadow(...)`；将 `clip-path` 专门写在内部装饰容器或 `::before` 丝带片上，投影会自动沿着燕尾轮廓生成。

### 问题 3（中度）：旋转的便利贴可能造成叠层遮挡（Stacking Context Trap）与小屏溢出
- **问题说明**：
  1. 给便利贴加上 `transform: rotate(0.5deg)` 会创建独立的 CSS 层叠上下文，如果便利贴内有 `<select>` 下拉或悬浮 tooltip，可能被后面的兄弟卡片压住；
  2. 移动端（`320px–560px`）容器边距较窄，微倾角会让角落超出屏幕引发横向滚动条；
  3. 过大的倾角（> `1.5deg`）在连续阅读大段文字时会让人眼疲劳。
- **解决方案**：
  - 倾角严格克制在 **`±0.3deg ~ ±0.55deg`**（视觉像自然随手贴上，但阅读不歪斜）；
  - 地图 Canvas 所在大容器、弹窗大段阅读区**严禁旋转**；
  - 卡片 `:hover` / `:focus-within` 瞬间抬高 `z-index: 5` 并归零为 `rotate(0deg)`；
  - `@media (max-width: 768px)` 统一切回 `transform: none`。

### 问题 4（性能）：大面积 SVG `feTurbulence` 在拖拽划线时可能掉帧
- **问题说明**：全屏底图或 400×400 地图区旁如果存在大尺寸实时算力的 SVG turbulence 滤镜，在用户高频触发 `PointerMove` 实时重绘 `<canvas>` 路线时，部分笔记本核显合成帧率可能从 60fps 掉到 30fps。
- **解决方案**：不要用实时逐帧 SVG 滤镜，而是用 **静态预定义 SVG Path（多点精细不规则撕裂轮廓 `mask-image` / `clip-path: polygon(...)`）+ CSS 多层背景纹理**。静态矢量路径由 GPU 直接缓存，划线路线重绘时保持满帧流畅。

### 问题 5（响应式适配）：侧边栏折叠成顶部横条时的书签朝向冲突
- **问题说明**：参考 `night-sugar-office` 架构，屏幕宽度 `≤ 560px` 时左侧 `82px` 侧边栏会折到顶栏下方变成横向一排导航条。如果竖向右侧燕尾的丝绸书签样式写死，横排时会显得方向别扭甚至互相遮挡。
- **解决方案**：为 `.nav-item` 书签的剪口和探出方向按断点拆开：桌面端向右水平探出剪燕尾；`≤ 560px` 移动端改为向下短幅垂坠或平直金色压线徽章，确保移动端同样精致可用。
